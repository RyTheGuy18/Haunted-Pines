# Level 0 — The Backrooms (repo: RyTheGuy18/Haunted-Pines)

Notes for future Claude sessions. Read this before changing anything.

First-person co-op Backrooms horror game for 1–4 players, played in the browser (desktop + phones, installable as a PWA). Survivors escape Level 0, then Level 1, then Level 37 (the Poolrooms), then Level 188 (the Hotel), then Level 852 (the Mall), then Level 2 (Pipe Dreams), then Level 52 (School Halls), then Level Fun (the party), then THE BASEMENT (v0.63), then THE WARD (v0.78, a holdout), while one player (or the computer) is **the Occupant** hunting them. The repo is still named Haunted-Pines, from an older scrapped concept (a foggy-woods campground); the game itself is "Level 0".

- Live: https://rytheguy18.github.io/Haunted-Pines/ (GitHub Pages, `main` branch, repo root)
- Owner: Ryan (GitHub `rytheguy18` / `RyTheGuy18`). Plays it with friends and younger brothers, mostly on phones.
- Current version: **v0.78.5** (shown bottom-right of the menu, `#ver`)

## Gameplay as it stands

**Level 0 (the office)** — **19×19** grid of 4 m cells (v0.28, was 16; `GRID_N(0)`, `CS=4`), wall height 2.8 m. 9 batteries. Three zones: office (yellow wallpaper/carpet), parking corner (concrete), "the pitfalls" (pits with ~1.2 m walkways; falling = death). Maze from DFS + random openings (`rng()<0.43` = how open), plus big halls, tight corridor blocks and a red room. The **clean office** was removed in v0.28 (Ryan): `L.clean = null`, its build/clock code is dead. Office + pitfalls floors use `rugTex` (pitfall walkways are one merged mesh with world-space UVs); the parking corner keeps concrete.
- Goal: find **3 fuses** → put them in the **breaker** → exit door opens → reach it.
- ~~Walls shift~~ **v0.62: no wall shifting anywhere any more (Ryan).** Both `doShift` calls in `hostTick` are gone (`doShift` itself is still there, unused).
- Items: batteries (flashlight), lockers (hide; hold breath bar; **the Occupant can't open lockers**). **Almond water, sanity and the rolling office chair were removed in v0.20, and throwable cans in v0.26.4 (Ryan's call — don't add back).** `L.cn`/`G.cn`/`throwCan` remain as empty/dead code. `G.aw`/`level.aw` still exist as empty arrays.
- Phones ring and give hints (sometimes "found you"). **v0.30:** ring = `phone-ring.mp3` (gain 0.32 since v0.31, every 4 s; **v0.35.2:** fades by distance from you, full inside `RING_NEAR` 10 m, silent past `RING_FAR` 22 m — Ryan: heard from too far away; Level 37's PA chime unchanged), answering (walk within 1.5 m) plays `phone-pick-up` then static; the voice says the direction **relative to where you're facing** (`relDir`: straight ahead / ahead off to your left / to your right / behind you…), and a faint arrow + "what · N m" (`#guide`, `setGuide`/`updateGuide`, 14 s) points the way and turns as you turn; on the hotel, if it's on another floor the arrow points to the nearest elevator landing ("elevator → floor N"). Wall phones (Level 0/1 + hotel) use `models/telephone.glb` (`phoneModel`/`fillPhone`, box phone until it loads). Lying EXIT signs, scrawls, doors to nowhere, wet footprints into walls (the off-the-hook phone was removed in v0.62.6).
- **The exit door** (both grid levels) is only put on a boundary cell that's not in a tight maze block or the pitfalls, has no tight/pit neighbours and no pillar at its corners (`exitOk`), preferring far cells. **v0.26.5:** the exit cell's inner edges are forced open and marked `L.fixed` (walls never shift there), so the door can't be walled in. Reachability was checked with a 0.2 m flood fill using the real `collide` + `inPit` (45 seeds × up to 25 shift rounds on Level 0, Level 1 too): always reachable.
- **The Async lab (v0.39, Ryan, from the "safety in horror games" video in the claude.ai project):** the round's one safe room, module `/* ===== the Async lab */` (just above `buildExtras`). Cells i 0..4, j 0..2 (20×12 m, ceiling `LAB_H` 4.0) in the survivors' corner; `genWalls` → `labWalls` opens the inside, walls it off from the maze except the **portal** edge `labPE()` = `hIdx(2,3)` (gate centre `LAB_GX,LAB_GZ` = 10,12), then reconnects the rest of the maze. All lab edges are `L.fixed`; lab cells are skipped for floors/ceilings/panels/`takeSlot` and marked `L.used`; `connected()` now checks the maze from cell (2,3) with the lab blocked (the door may be shut). Look (Ryan's reference picture): grey tile floor, ceiling tiles, concrete panel walls (planes in front of the shared wallpaper boxes), 7 electrical cabinets on the east wall, an observation booth with a lit yellow window (NW), desks/chairs/papers/an "A" mug/CRT, whiteboard, ASYNC sign, blue-white barrier, a steel gate frame with hazard stripes, a shimmering additive `portalMat` in the opening, 8 ceiling panels (`labPanels`, `p.lab`; lab cells share them in `panelAt`, so `updatePanels` dedupes). Everyone spawns at `L.spawn` (10, 3.8) facing the portal (`L.spawnYaw` = π). The monster spawns ≥ 34 m from the portal (`farLab`).
  - **v0.39.1 (Ryan: clipping, and the booth was a flat picture):** every decal in the lab (signs, whiteboard, panel screen, floor tape, hatch border/label, papers, CRT screens) uses `dec()` = polygonOffset and sits ≥ 0.012–0.04 off its surface, so PSX vertex snapping can't make it fight the wall/floor. The **observation booth** is now a real room you can walk into: walls built in pieces around a glass window (front, z 3.8) and a doorway (east wall, z 2.3–3.25) with the door swung open inside, yellow wallpaper (`paperTex`) inside, carpet, ceiling tiles, its own ceiling light (the lab panel for cell (0,0) moved to (2.35, 2.0) at 2.66 m), a desk with two CRTs (one mirrors the blast door panel, `labDispTex`), keyboard, papers, desk lamp, office chair, filing cabinet, corkboard, clock. Collision = slabs per wall + furniture.
  - **AI ignores the lab:** `aiTick` drops survivors inside (`inLab`), never paths/wanders/dashes in (moves that end inside are reverted), no computer kills inside; `darkHunt` and the Lurker (`lrBlock`, `ok`) skip it too. A **player** Occupant can walk in while the door is open.
  - **Blast door** (host `hostLab`, state `G.ld` shut, `G.lp` power %, `G.lbo` blackout s): survivors press the panel right of the gate (`LAB_PANEL`, `labAction` → `{k:'ldoor'}` → `labUse`). Shut = `walls[labPE()] = 1` on every client (`updateLab`; `L.noDraw` hides the wall box, a rolling shutter is drawn instead). Drains `LAB_DRAIN` 2.5 %/s (40 s), recharges open 100 in 75 s, needs `LAB_MIN` 10 % to shut, beeps under 25 %. At 0 the door slams open and **power fails for `LAB_BO` 35 s**: `panelBright` = 0 for every Level 0 panel (stutters back in the last 1.6 s), `inDark` is true everywhere on Level 0 (Lurker creeps, computer `darkHunt`s anyone outside the lab), lab glow materials dim, `updateZoneEnv` goes near-black. Panel screen (`drawLabPanel`) + the HUD `#side` line in the lab (`labStatus`) show door/power/**entity sensor** (`labSensor`: clear / nearby 20 m / at the portal 8 m / inside).
  - **Anti-camping: the ESCAPE HATCH** (`LAB_HATCH` floor hatch, one way): hold nothing, press USE → 2.4 s crawl (`hatchT`, black screen) → out of one of 3 far manhole hatches (`level.lab.exits`, ≥ 26 m from the portal, not pits/tight blocks), never one within 14 m of the Occupant; a vent clang plays there for everyone (the computer comes to look if within 24 m).

## Multiplayer

PeerJS, host's browser is the hub (star). Room code = 4 letters, peer id `level0-v1-CODE`. Max 4 players.
- Host owns the authoritative state `G` (see `freshState()`), broadcasts it every 0.1 s in play; clients send `presence` (position, flags) every 0.1 s and `use` requests (`useReq` → `applyUse` on the host). One-off sounds go over `snd`.
- `G.lv` = level (0/1/2), `G.gen` generators, `G.fz` fuses, `G.dead/esc/kl`, `G.dg` disguise, `G.ov` Occupant voice option, etc. Level geometry is rebuilt identically on every client from a seed (`baseSeed`, `lvSeed(k)`), walls synced as a hex bitmask.
- Lobby: host picks who's the Occupant (random / computer / a player), skins per player, OCCUPANT VOICE option, COMPUTER difficulty (`G.df`), START AT level (`G.sl` 0–6 = Level 0/1/37/188/852/2/52; menu button `bLv1` for solo, lobby `bLv` for host; `localStorage['lvl0_start']`). `setupLevel(k)` builds a level into `G` (used by `advanceLevel` and by `hostStartRound` when starting later). End screen: PLAY AGAIN or **BACK TO LOBBY** (keeps the room together).
- `#localnet` in the URL swaps PeerJS for a BroadcastChannel transport (same-browser tabs) — used for automated tests. It has **no voice calls**.

**Proximity voice chat** (`voice` object): PeerJS audio calls, one per pair (lower peer id calls). Opt-in via VOICE CHAT button (menu, lobby, settings). Rules: lobby/end = everyone full volume; in a round survivors fade out by ~12 m (muffled through walls); the Occupant hears survivors; **nobody hears the Occupant** unless the host turned on **OCCUPANT VOICE: MONSTER** — then survivors within ~10 m hear it through `monsterVoice()` (delay-line pitch shifter ~10 semitones down + 38 Hz growl ring-mod + distortion + echo, applied on the receiving side); dead players only talk to dead players. Mic meter under the objective (quiet / HEARD / LOUD). V mutes. Confirmed working by Ryan with real players.
- **v0.28.1 (Ryan: iPhone voice unreliable, others could barely hear him):** the raw mic (`voice.raw`, from `getMic()` with `SET.mic` as deviceId, falls back to default) feeds a Web Audio chain `micChain()` = high-pass 85 Hz → **MIC BOOST** gain (`SET.mg`, default 220% on iOS / 160% elsewhere) → compressor → ×2 make-up → limiter → `MediaStreamDestination`; **that** stream (`voice.stream`) is what calls send, so switching mics (`switchMic` → `plugMic`) only swaps the source node, no renegotiation. The mic meter / noise detection still reads the raw mic (`voice.an`), so boosting doesn't make you louder to the Occupant. iPhone: `navigator.audioSession.type` = 'play-and-record' while the mic is on and right before `getMic` asks (`setAudioSession(true)`), 'auto' otherwise. **Never 'playback'**: in that mode iOS refuses the mic with NotAllowedError even when Safari's mic setting is Allow — v0.28.1–0.28.7 set it in `sfx.init()` and broke the iPhone mic (fixed v0.28.8). `wakeAudio()` resumes a suspended/interrupted AudioContext on any touch/click/visibility and re-acquires a mic track iOS ended (`micLost`). Calls: `opusTweak` sdpTransform (in-band FEC, 40 kbps, mono) on call + answer; `voiceWatchdog` (2 s) closes calls with no stream after 12 s or ICE failed/disconnected ~8 s, and re-dials are spaced 3 s (`voice.retry`); if a remote's inbound `totalAudioEnergy` rises while our analyser on that call is pure silence 3 times, the call switches to direct `<audio>` playback (`c.direct`, volume via `el.volume`, no 3D). Untested on a real iPhone (sandbox can't reach PeerJS).
- **Background audio off (v0.28.7, Ryan):** `audioOff()` on `visibilitychange` hidden / `pagehide` / `freeze` suspends `sfx.ctx` (all sound + voice), pauses call `<audio>` elements and releases the mic (stops `voice.raw`, sets `voice.lost`; the sent `voice.stream` is the chain's destination so calls stay up, just silent). `audioOn()` on visible / `pageshow` / `resume` resumes and re-opens the mic via `micLost()`. `wakeAudio()`/`micLost()` do nothing while away.
- **Mic permission help (v0.28.6, Ryan: it just said "mic blocked")**: `getUserMedia` is always called straight from a tap (needed for the iPhone prompt). On failure `micHelp(e)` opens `#micHelp` with a reason per error (NotAllowed = the phone remembers an earlier Don't Allow; NotFound; NotReadable = another app has the mic) and iPhone steps (Safari: aA → Website Settings → Microphone; home-screen app: Settings → Apps → Safari → Microphone → Ask, then reopen the app). Buttons: ASK AGAIN (calls `voiceEnable(true)` from that tap), RELOAD & ASK AGAIN (sets `lvl0_askmic`; after reload the first tap anywhere asks), NOT NOW. `getMic` falls back to `{audio:true}` on Overconstrained/TypeError.
- **Devices** (settings, v0.28.1): MICROPHONE select (`#sMic`, `SET.mic`), SPEAKER/HEADPHONES select (`#sSpk`, `SET.spk`, `AudioContext.setSinkId`, only where supported — Chrome/Edge desktop; disabled with a note on iPhone/Safari/Firefox), MIC BOOST slider + a live level meter. `fillDevices()` runs when settings open, after the mic is allowed and on `devicechange`.

## How to work on it

- **Edit `index.html` with exact-match replacements** (Python `rep(old,new)` asserting one match worked well). Then syntax-check the module: extract the `<script type="module">` body to a `.mjs` and run `node --check`.
- **Module TDZ trap**: top-level code runs top to bottom; calling something that touches `sfx` (declared late) from earlier top-level code crashes. Defer with `queueMicrotask` or call only from event handlers/frame.
- **Testing**: Playwright + system Chrome (`/usr/bin/google-chrome`, flags `--use-gl=swiftshader --enable-unsafe-swiftshader`). Nov 2026: `chromium.launch()` hung in the sandbox — start Chrome yourself (`--headless=new --no-sandbox --remote-debugging-port=9333 --user-data-dir=<fresh dir>`) and `connect_over_cdp`; run python with `-u` and write output to a file; poll `__hp` with `wait_for_timeout` + `evaluate` (`wait_for_function` timed out); a fresh profile every run or Chrome serves the old index.html, serve the repo with `python3 -m http.server 8765 --directory <repo>` **started in the same command** (background servers die between turns). `window.__hp` exposes internals (G, me, level, MON, sfx, voice, ability, contextAction, …) for tests. Two-player tests: two pages in one context with `#localnet`; add `--disable-background-timer-throttling --disable-renderer-backgrounding --disable-backgrounding-occluded-windows` and `bring_to_front()` the page that must tick (the host runs the simulation). Headless runs at low FPS, so game time runs slow — poll for conditions instead of fixed waits. Fake mic: `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream`.
- Can't test real PeerJS (cloud server unreachable from the sandbox) — voice/online needs Ryan to try it.
